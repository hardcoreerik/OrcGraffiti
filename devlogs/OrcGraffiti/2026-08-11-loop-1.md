### AS-1: orcgraffiti CLI skeleton

Per `docs/OrcGraffiti/Agent_Surface.md` §6/§13, added a new headless binary:

- `src/orcgraffiti_cli/orcgraffiti.cpp` — single-TU executable, links
  `libslic3r` only (no wx/ImGui/OpenGL/Plater), following the
  `OrcaSlicer_profile_validator` pattern (NANOSVG implementation macros
  before any libslic3r header, since several headers transitively include
  nanosvg.h without the implementation macro).
- Commands: `version`, `help`, `info <input> [--report path.json]`.
- `info` loads a model via `Model::read_from_file`, walks
  objects/volumes, and reports triangle/vertex counts, bbox, MMU-paint
  presence (`ModelVolume::is_mm_painted()`), and a topology fingerprint
  (`ImagePaint::fingerprint_from_arrays`) — matching the §6.4 report sketch.
- Exit codes per §6.2: 0 success, 2 domain error (model load failure).
- `src/CMakeLists.txt`: new `orcgraffiti` target added next to
  `OrcaSlicer_profile_validator`, same link set
  (`libslic3r boost_headeronly libcurl OpenSSL::SSL OpenSSL::Crypto`).
- New fixture: `tests/orcgraffiti_cli/fixtures/unit_cube.stl` (hand-written
  ASCII STL, 12 triangles / 8 vertices) — no OneDrive/external dependency,
  matching Agent_Surface.md §12.2 fixture guidance.

**Verified manually:**
```
orcgraffiti.exe info unit_cube.stl
→ {"ok": true, "objects": [{"volumes": [{"triangle_count": 12, "vertex_count": 8, ...}]}]}

orcgraffiti.exe info missing.stl
→ {"ok": false, "error": {"code": "ModelLoadFailed", ...}}, exit 2
```

**AS-1 exit gate met**: `info` JSON on a fixture returns stable, correct
output. ImagePaint core suite unaffected (15/15 ctest still green after
the CLI addition).
