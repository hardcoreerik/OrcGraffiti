## What Was Done

### AS-2: paint --dry-run

`src/orcgraffiti_cli/orcgraffiti.cpp` gained a `paint` command:

```
orcgraffiti paint <input> --image <path> --filaments <json>
    [--object i] [--volume i] [--view front|back|left|right|top|bottom]
    [--colors n] [--quality fast|threepoint|gaussian7] [--merge overwrite|preserve]
    --dry-run [--report path.json]
```

- View presets (`view_preset()`) are locked to the golden-test conventions
  already established in `test_image_paint_pipeline.cpp`: `front` = look
  `(0,1,0)` up `(0,0,1)`; `top` = look `(0,0,-1)` up `(0,1,0)` (matches the
  "real file with fit paints front of plate" flat-plate test). `back`/
  `left`/`bottom` are the geometric mirror, not yet locked by their own
  golden test — noted as a gap.
- The image is decoded once via `ImagePaint::decode_image`, then used both
  for `fit_planar_projection`'s aspect argument and the pre-decoded
  `run_image_paint(request, image, cancel)` overload — avoids a double
  decode.
- Filament palette loader (`load_filaments`) matches the JSON shape in
  Agent_Surface.md §6.7 (`index`/`name`/`color_hex`).
- Report shape matches §6.8: `image`, `projection`, `fingerprint`,
  `diagnostics`, `matches`, `error`.
- `--out`/write mode is explicitly rejected right now with a clear
  `"write mode (--out) is AS-3 and not yet implemented; pass --dry-run"`
  error (exit 1) rather than silently no-opping.

**Manually verified** against `unit_cube.stl` + real `garth.jpg` + a new
4-filament fixture (`tests/orcgraffiti_cli/fixtures/filaments.json`):
`ok:true`, 2/12 faces painted (top face, front view), 2 cluster matches —
consistent with the existing pipeline integration test's shape for a
similar setup. Error paths verified: bad `--view` (exit 1), missing
`--dry-run` (exit 1), bad image path → `ImageOpenFailed` (exit 2).

### CLI contract tests in ctest

Agent_Surface.md §12.1 lists "CLI contract tests: golden JSON for
info/paint --dry-run on fixture cube" as a required coverage layer, distinct
from the Catch2 core suite. Added 4 `add_test()` entries in
`src/CMakeLists.txt` (label `CLI`), gated by `BUILD_TESTS`, that invoke the
`orcgraffiti` binary as a subprocess and check stdout against a regex:

- `orcgraffiti_cli_version` — version string present
- `orcgraffiti_cli_info_fixture` — `unit_cube.stl` reports `triangle_count: 12`
- `orcgraffiti_cli_info_missing_file` — missing file reports `ModelLoadFailed`
- `orcgraffiti_cli_paint_requires_dry_run_or_out` — write-mode-not-implemented error surfaces

Note: initially tried `WILL_FAIL TRUE` + `PASS_REGULAR_EXPRESSION` together
for the two error-path tests — CTest reported spurious failures
("Required regular expression found." on a passing match). Dropped
`WILL_FAIL`; `PASS_REGULAR_EXPRESSION` alone makes CTest judge pass/fail
purely on stdout content, independent of the (nonzero) exit code, which is
what these tests actually need to assert.

**19/19 tests pass** (`ctest -R "image_paint|orcgraffiti"`): 15 core
ImagePaint + 4 new CLI contract tests.

### AS-3 scoped, not attempted

Investigated the 3MF write path (`store_bbs_3mf` / `StoreParams` in
`src/libslic3r/Format/bbs_3mf.hpp`) and the existing GUI apply logic
(`ImagePaintJob::finalize`, `src/slic3r/GUI/Jobs/ImagePaintJob.cpp:43-85`).
Decided **not** to implement this loop:

- `Model::read_from_file` needs to be called with real `DynamicPrintConfig*`
  / `PlateDataPtrs*` / `vector<Preset*>*` (currently `nullptr` in `info`/
  `paint`) to round-trip a 3MF's config and plate data losslessly — getting
  this wrong risks silently corrupting profile/plate data, which directly
  violates INV-008 (no printer/profile mutation) and this project's
  explicit "no shortcuts on safety invariants" culture.
- `PlateDataPtrs` are raw pointers requiring `release_PlateData_list`
  cleanup — an ownership footgun to get right on the first pass without a
  human able to inspect the result in the GUI.
- Per Agent_Surface.md §13, AS-3's actual exit gate is "GUI reopen proof" —
  a human confirming painted faces are visible in Orca's gizmo after
  reopening the CLI-written 3MF. This loop has no GUI/display access to
  perform that check itself.

Wrote the full technical plan into `AI_STATUS.md` (steps 1-6) so the next
iteration — automated or human — can execute it directly instead of
re-deriving it.
