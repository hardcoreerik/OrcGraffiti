## What Was Done

### AS-4: SKILL.md rewrite

The prior `docs/OrcGraffiti/skills/orcgraffiti-cli/SKILL.md` was written
during AS-0 (spec freeze) as a template — it documented flags from
`Agent_Surface.md`'s full future design (`--auto-fit`, `--filaments-from-
project`, `verify` command) that were never implemented, and said nothing
about `--dry-run`/`--out` mutual exclusivity, `--force`, `--allow-in-place`,
or the two known limitations found during AS-3 (plain-3MF profile loss,
broken paint self-check).

Rewrote it to describe exactly what `orcgraffiti help` actually prints and
what the binary actually does:

- Flags table matches current `PaintOptions` parsing 1:1
- Cookbook: inspect → build a filament palette → dry-run → write, each
  step using the committed fixtures (`unit_cube.stl`, `filaments.json`,
  `sample_project.3mf`)
- "Known limitations" section states the AS-3 v1 scope tradeoffs plainly
  (plain 3MF, no profile preservation, no working paint self-check) instead
  of letting an agent following this skill discover them by surprise
- Failure remediation table matches actual error codes/messages from the
  binary

**Verified the cookbook, not just wrote it** (AS-4's exit gate per
`Roadmap.md` §20 is "cookbook works," not "cookbook exists"): ran every
documented command against the fixtures — `info` on `sample_project.3mf`,
dry-run and `--out` paint on `unit_cube.stl` + `garth.jpg`, and the
`--force`/no-`--force` overwrite behavior — all matched documented
behavior and exit codes exactly.

### Small fix in passing

`orcgraffiti.cpp`'s help text still said `paint <input> ... (dry-run only
for now)` — stale since AS-3 landed `--out` in the previous commit. Fixed
alongside the skill rewrite so `help` output and `SKILL.md` stay in sync.
