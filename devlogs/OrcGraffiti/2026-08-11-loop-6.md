### Root cause found: missing `<assemble_item>`

Diffing the reference file's `Metadata/model_settings.config` against the
loop-3 BBS-writer output showed one structural difference: the reference
had a populated `<assemble><assemble_item object_id="2" instance_id="0"
transform="..." offset="..." /></assemble>`; ours had an empty
`<assemble></assemble>`. Traced this to `bbs_3mf.cpp:8186` — the exporter
only emits an `<assemble_item>` for instances where
`ModelInstance::is_assemble_initialized()` is true, which requires an
explicit `set_assemble_transformation()` call. A freshly-loaded model's
instances never have this set by default.

### Fix and verification

Re-implemented the write path (previously reverted in loop 3, replaced
with the plain writer in loop 4):
- Kept the loop-3 fix: synthesize a single default `PlateData` when
  `plate_data` is empty (non-3MF inputs).
- New: `instance->set_assemble_transformation(instance->get_transformation())`
  on every instance before calling `store_bbs_3mf`.
- New: `SaveStrategy::Zip64 | SaveStrategy::UseLoadedId` (the latter
  matching `OrcaSlicer.cpp`'s own `CLI::export_project`, on the theory
  that a real, known-working code path's flags are a safer bet than
  guessing).

**Verified:** `paint --out` on `unit_cube.stl` + `garth.jpg`, then
`orcgraffiti info` on the result, now reports `has_mmu_paint: true`
(previously `false` on every prior attempt). Hand-inspected the raw zip:
`<assemble_item>` is now populated exactly like the reference file's
shape. Fingerprint/geometry still round-trip exactly (unchanged from
earlier attempts — that part was never broken).

Generated a fresh file (`gui_check_bbs_v2.3mf`) and sent it to the user
for the real confirmation — **still pending at end of this loop.** Updated
all docs to reflect "own self-check passes, human confirmation pending,"
not "confirmed working," to stay honest until that lands.

### Phase 7: cylindrical projection (while waiting on GUI confirmation)

Implemented `Roadmap.md` §11's cylindrical projection formula in
`src/libslic3r/ImagePaint/Projection.{hpp,cpp}`:
`CylinderFrame`/`make_cylinder_frame` (mirrors `ProjectorFrame`/
`make_projector_frame`'s degenerate-input handling) and
`CylindricalProjectionSettings`/`project_cylindrical`, following
`d = p - O; height = dot(d,A); radial = d - height*A; theta =
atan2(dot(radial,T), dot(radial,R)); u = (theta - theta_start) /
wrap_angle; v = 0.5 - height / height_mm` from the spec exactly.

Resolved one ambiguity the terse roadmap formula left open: raw `theta`
from `atan2` is in `(-pi, pi]`, not `[0,1]`. Interpreted `seam_angle` as
the angle mapping to `u=0.5` (a "front reference direction"), with the
UV seam itself at `seam_angle + pi` — the standard cylindrical-UV
convention, and documented the reasoning in a code comment rather than
silently picking an interpretation.

9 new tests (frame orthonormality, degenerate rejection, quarter-turn/
opposite-side UV mapping, height-to-v centering, radius-range filtering,
partial-wrap exclusion, full-wrap seam continuity) — all passed on first
run against hand-derived expected values. Not yet wired into
`FaceSampler`/`ImagePaintPipeline` or the CLI — projection math only, per
the roadmap's own phased task breakdown.
